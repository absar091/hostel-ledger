## 2024-05-18 - Missing Path Parameter Validation in Express Routes
**Vulnerability:** Found missing validation on the `groupId` parameter in `app.get('/api/budgets/group/:groupId')` and `app.post('/api/budgets/group/:groupId')` endpoints. Unvalidated route parameters were being directly interpolated into Firebase Realtime Database queries (e.g., `db.ref(\`budgets/${groupId}\`)`). While Express.js naturally prevents typical `../` path traversal in parameters, other special characters could lead to data format issues or unexpected query behavior in Firebase.
**Learning:** In Express APIs connected to Firebase, path parameters derived from `req.params` must be explicitly validated against an allowlist pattern (using the codebase's existing `isValidFirebaseId` utility function) before being used in database queries, ensuring they are validated as strictly as `req.body` payloads.
**Prevention:** Always apply `isValidFirebaseId(param)` checks to route parameters used in database paths. Ensure the `isValidFirebaseId` function is correctly imported from the `utils/validation.js` module in the file.
