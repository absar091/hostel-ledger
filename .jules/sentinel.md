## 2024-05-24 - Fix NoSQL Injection in clientTxnId
**Vulnerability:** The `/api/add-expense` and `/api/record-payment` endpoints accepted an unvalidated `clientTxnId` from the request body and used it directly in a Firebase Realtime Database path query: `db.ref(\`processedTxns/\${clientTxnId}\`)`. This allowed potential NoSQL injection and path traversal (e.g., passing paths containing `/` or special characters) to access or overwrite unintended data.
**Learning:** Client-provided identifiers used in database paths must always be strictly validated against an allowed format (e.g., alphanumeric strings of a certain length) before interpolation. The Firebase Admin SDK does not inherently protect against path traversal if the interpolated string contains `/`.
**Prevention:** Always validate IDs using functions like `isValidFirebaseId` (which checks against a regex like `/^[a-zA-Z0-9_-]+$/`) before using them in `db.ref()` paths.
