## 2025-04-06 - Replacing Native Title Attributes with Radix Tooltips
**Learning:** Native `title` attributes on interactive elements provide a delayed, inconsistently styled, and poorly accessible tooltip experience. When integrating Radix UI tooltips, it's critical to explicitly remove the native `title` attribute to prevent a "double-tooltip" effect where both the custom and native tooltips appear simultaneously, confusing users and screen readers. Additionally, tooltips must be globally wrapped in `<TooltipProvider>` to prevent application crashes due to missing context.
**Action:** Always replace native `title` attributes on icon-only buttons with Radix `<Tooltip>` components, ensuring the native attribute is removed. Use `<TooltipTrigger asChild>` to prevent invalid HTML nesting, and wrap the component tree with `<TooltipProvider>`. Utilize `useTranslation` for the tooltip and `aria-label` content.
## 2024-05-18 - Added tooltips and aria-labels for Transaction Detail Modal icon buttons
**Learning:** Found several icon-only buttons in the transaction detail modal (Share as Image, Close, Copy Reference, View on Maps) that were missing accessible names or relying solely on `title` attributes. For portal-rendered modals with a high z-index, replacing native `title` with Radix UI `Tooltip` requires adding explicit `z-[110]` to the `TooltipContent` to prevent the tooltip from rendering behind the backdrop. Also, because `TooltipContent` escapes the DOM tree in a portal, it's essential to retain the `aria-label` on the trigger `<button>` to ensure screen readers correctly announce the button's purpose.
**Action:** Always wrap Radix UI Tooltips in `TooltipProvider` when not globally provided, explicitly add `aria-label` to the trigger buttons, and for overlays, verify z-index of the `TooltipContent` to ensure visibility.
