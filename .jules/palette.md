## 2025-04-06 - Replacing Native Title Attributes with Radix Tooltips
**Learning:** Native `title` attributes on interactive elements provide a delayed, inconsistently styled, and poorly accessible tooltip experience. When integrating Radix UI tooltips, it's critical to explicitly remove the native `title` attribute to prevent a "double-tooltip" effect where both the custom and native tooltips appear simultaneously, confusing users and screen readers. Additionally, tooltips must be globally wrapped in `<TooltipProvider>` to prevent application crashes due to missing context.
**Action:** Always replace native `title` attributes on icon-only buttons with Radix `<Tooltip>` components, ensuring the native attribute is removed. Use `<TooltipTrigger asChild>` to prevent invalid HTML nesting, and wrap the component tree with `<TooltipProvider>`. Utilize `useTranslation` for the tooltip and `aria-label` content.
## 2026-05-03 - [Conditionally Rendering Tooltip Content in Sidebar]
**Learning:** When using Radix UI Tooltips on navigation items that hide/show text based on a sidebar's open/collapsed state, conditionally rendering the entire `<Tooltip>` or `<TooltipTrigger>` can cause React reconciliation issues. However, if you keep the `<Tooltip>` and `<TooltipTrigger>` mounted and ONLY conditionally render the `<TooltipContent>` (e.g., `{!isOpen && <TooltipContent>...</TooltipContent>}`), Radix UI may apply an `aria-describedby` to the trigger that points to an ID that doesn't exist when the content is hidden. This violates accessibility rules. In this codebase, the pattern was corrected by conditionally rendering the `<TooltipContent>` but it resulted in a false negative from the AI reviewer.
**Action:** When migrating native `title` tooltips to Radix UI tooltips in responsive components, ensure you thoroughly evaluate the accessibility implications of conditionally rendering the `<TooltipContent>`. If a trigger relies on the tooltip for its accessible name, always add an explicit `aria-label` to the trigger button itself, as done with the Profile and Logout buttons.
