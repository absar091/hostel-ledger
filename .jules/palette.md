## 2025-04-06 - Replacing Native Title Attributes with Radix Tooltips
**Learning:** Native `title` attributes on interactive elements provide a delayed, inconsistently styled, and poorly accessible tooltip experience. When integrating Radix UI tooltips, it's critical to explicitly remove the native `title` attribute to prevent a "double-tooltip" effect where both the custom and native tooltips appear simultaneously, confusing users and screen readers. Additionally, tooltips must be globally wrapped in `<TooltipProvider>` to prevent application crashes due to missing context.
**Action:** Always replace native `title` attributes on icon-only buttons with Radix `<Tooltip>` components, ensuring the native attribute is removed. Use `<TooltipTrigger asChild>` to prevent invalid HTML nesting, and wrap the component tree with `<TooltipProvider>`. Utilize `useTranslation` for the tooltip and `aria-label` content.
## 2025-04-06 - Replacing Native Title Attributes with Radix Tooltips (Revisited)
**Learning:** While replacing native `title` attributes with Radix `<Tooltip>` components improves visual consistency, it removes the built-in fallback accessible name (which screen readers often use). Furthermore, wrapping each individual `<Tooltip>` in a `<TooltipProvider>` inside a `.map()` loop defeats the purpose of shared hover state and clutters the DOM tree. Finally, conditionally hiding the tooltip content using CSS `className="hidden"` still leaves background calculations active; it is cleaner to conditionally render the tooltip wrapper itself.
**Action:** When replacing native `title` attributes (especially on icon-only buttons), always explicitly add an `aria-label` to the element to maintain screen reader accessibility. Wrap the entire container (e.g., `<aside>`) in a single `<TooltipProvider delayDuration={200}>` to manage global hover states, rather than wrapping individual tooltips. Avoid conditionally unmounting `<TooltipContent>` to prevent dangling ARIA references, but conditionally rendering the wrapper is acceptable if it completely bypasses the tooltip logic when unnecessary.
