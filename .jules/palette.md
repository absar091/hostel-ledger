## 2025-04-06 - Replacing Native Title Attributes with Radix Tooltips
**Learning:** Native `title` attributes on interactive elements provide a delayed, inconsistently styled, and poorly accessible tooltip experience. When integrating Radix UI tooltips, it's critical to explicitly remove the native `title` attribute to prevent a "double-tooltip" effect where both the custom and native tooltips appear simultaneously, confusing users and screen readers. Additionally, tooltips must be globally wrapped in `<TooltipProvider>` to prevent application crashes due to missing context.
**Action:** Always replace native `title` attributes on icon-only buttons with Radix `<Tooltip>` components, ensuring the native attribute is removed. Use `<TooltipTrigger asChild>` to prevent invalid HTML nesting, and wrap the component tree with `<TooltipProvider>`. Utilize `useTranslation` for the tooltip and `aria-label` content.
## 2025-04-06 - Fixing Sidebar Tooltip Accessibility
**Learning:** Native `title` attributes on sidebar navigation links, profile, and logout buttons resulted in a jarring, delayed tooltip that lacked accessibility guarantees. It's critical to ensure Radix `<Tooltip>` wrappers correctly inherit React keys inside mapped loops (e.g., `<Tooltip key={item.id}>`) to satisfy both rendering logic and linting. Furthermore, transitioning mapped collections from implicit `any` types to fully typed interfaces (e.g., `{id: string, icon: React.ElementType, label: string, path: string, badge?: number}`) greatly bolsters maintainability while fixing `eslint` warnings.
**Action:** When wrapping mapped elements with `<Tooltip>` components, explicitly move the React `key` from the original inner element to the outer `<Tooltip>`. Refactor array item typing to be explicitly defined. Conditionally render `<TooltipContent>` (e.g., `{!isOpen && <TooltipContent>...}`) to prevent tooltips from cluttering the UI when not collapsed.
