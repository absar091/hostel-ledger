## 2025-04-06 - Replacing Native Title Attributes with Radix Tooltips
**Learning:** Native `title` attributes on interactive elements provide a delayed, inconsistently styled, and poorly accessible tooltip experience. When integrating Radix UI tooltips, it's critical to explicitly remove the native `title` attribute to prevent a "double-tooltip" effect where both the custom and native tooltips appear simultaneously, confusing users and screen readers. Additionally, tooltips must be globally wrapped in `<TooltipProvider>` to prevent application crashes due to missing context.
**Action:** Always replace native `title` attributes on icon-only buttons with Radix `<Tooltip>` components, ensuring the native attribute is removed. Use `<TooltipTrigger asChild>` to prevent invalid HTML nesting, and wrap the component tree with `<TooltipProvider>`. Utilize `useTranslation` for the tooltip and `aria-label` content.

## 2025-04-06 - Enhancing Screen Reader and Keyboard Accessibility on Custom Cards
**Learning:** Custom interactive cards built using `<button>` (like `GroupCard`) often contain disjointed pieces of information visually distributed across the component (e.g., name on the left, balance on the right). By default, screen readers read these out as fragmented, confusing text. Furthermore, if these custom components lack explicit focus states (like `focus-visible`), keyboard users cannot clearly identify which element has focus.
**Action:** When creating complex interactive card components, always provide a comprehensive, single-sentence `aria-label` on the root `<button>` that summarizes all the critical information logically (e.g., "Group name with X members. You owe Y."). Additionally, explicitly define keyboard focus styles using utilities like `focus-visible:outline-none focus-visible:ring-2` to ensure the interaction state is visually prominent.
