## 2025-04-06 - Replacing Native Title Attributes with Radix Tooltips
**Learning:** Native `title` attributes on interactive elements provide a delayed, inconsistently styled, and poorly accessible tooltip experience. When integrating Radix UI tooltips, it's critical to explicitly remove the native `title` attribute to prevent a "double-tooltip" effect where both the custom and native tooltips appear simultaneously, confusing users and screen readers. Additionally, tooltips must be globally wrapped in `<TooltipProvider>` to prevent application crashes due to missing context.
**Action:** Always replace native `title` attributes on icon-only buttons with Radix `<Tooltip>` components, ensuring the native attribute is removed. Use `<TooltipTrigger asChild>` to prevent invalid HTML nesting, and wrap the component tree with `<TooltipProvider>`. Utilize `useTranslation` for the tooltip and `aria-label` content.
## 2025-05-27 - Replacing Native Title Attributes with Radix Tooltips in Sidebar
**Learning:** When refactoring interactive elements like sidebar navigation items to use custom Radix Tooltips instead of native `title` attributes, it is critical to conditionally wrap only the trigger and content when the specific interaction state (e.g., collapsed sidebar) is active. Failing to provide the wrapping `<TooltipProvider>` around the component boundary causes app crashes, while retaining native titles alongside custom tooltips leads to accessibility regressions via double announcements on screen readers.
**Action:** Always replace native `title` attributes with `<Tooltip>` + `<TooltipTrigger asChild>` properly scoped, ensuring the native attribute is completely removed and the entire functional UI section (e.g., `<aside>`) is wrapped in a `<TooltipProvider>`. Use `aria-label` internally as a fallback screen-reader target if the tooltip's content matches it.
