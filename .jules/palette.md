## 2025-04-06 - Replacing Native Title Attributes with Radix Tooltips
**Learning:** Native `title` attributes on interactive elements provide a delayed, inconsistently styled, and poorly accessible tooltip experience. When integrating Radix UI tooltips, it's critical to explicitly remove the native `title` attribute to prevent a "double-tooltip" effect where both the custom and native tooltips appear simultaneously, confusing users and screen readers. Additionally, tooltips must be globally wrapped in `<TooltipProvider>` to prevent application crashes due to missing context.
**Action:** Always replace native `title` attributes on icon-only buttons with Radix `<Tooltip>` components, ensuring the native attribute is removed. Use `<TooltipTrigger asChild>` to prevent invalid HTML nesting, and wrap the component tree with `<TooltipProvider>`. Utilize `useTranslation` for the tooltip and `aria-label` content.

## 2024-06-27 - Replace native tooltips with accessible Radix UI tooltips
**Learning:** Native `title` tooltips on icon-only buttons cause poor screen reader experiences because they are announced awkwardly, and they provide no style control. Replacing them with Radix UI `<Tooltip>` components while preserving `aria-label`s on the `<button>` itself (with `asChild` on `<TooltipTrigger>`) ensures robust accessibility, a consistent visual design language, and customizable z-index positioning for complex layouts. Additionally, always explicitly add `focus-visible` ring styling to icon-only buttons to guarantee keyboard navigability.
**Action:** Whenever introducing icon-only buttons or replacing native `title` attributes, implement Radix UI `<Tooltip>` and explicitly set `aria-label` on the underlying interactive element along with `focus-visible:ring-X` styles.

## 2024-06-27 - Conditionally apply aria-label when hiding text
**Learning:** According to ARIA specifications, `aria-label` completely overrides the text content of an element. When enhancing interactive elements that conditionally hide their text (like collapsible sidebar items), conditionally apply `aria-label` (e.g., only when the text is visually hidden) to prevent screen reader accessibility regressions, such as silencing nested notification badges.
**Action:** When adding `aria-label` to buttons that contain dynamic text or badges, ensure it is only applied when the textual content is hidden from screen readers, or ensure it perfectly matches the visible text + badge count.
