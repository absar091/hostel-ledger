## 2025-04-06 - Replacing Native Title Attributes with Radix Tooltips
**Learning:** Native `title` attributes on interactive elements provide a delayed, inconsistently styled, and poorly accessible tooltip experience. When integrating Radix UI tooltips, it's critical to explicitly remove the native `title` attribute to prevent a "double-tooltip" effect where both the custom and native tooltips appear simultaneously, confusing users and screen readers. Additionally, tooltips must be globally wrapped in `<TooltipProvider>` to prevent application crashes due to missing context.
**Action:** Always replace native `title` attributes on icon-only buttons with Radix `<Tooltip>` components, ensuring the native attribute is removed. Use `<TooltipTrigger asChild>` to prevent invalid HTML nesting, and wrap the component tree with `<TooltipProvider>`. Utilize `useTranslation` for the tooltip and `aria-label` content.
## 2024-05-18 - Radix UI Tooltip implementation
**Learning:** When using Radix UI `Tooltip` on icon-only buttons, the Tooltip needs to be wrapped by a `TooltipProvider`. This was missing in the `TransactionDetailModal.tsx` file for the "Share as Image" and "Copy Reference" buttons, relying on standard browser title attributes instead. This can result in two tooltips appearing, and is generally less accessible and visually appealing than standardizing the tooltips.
**Action:** When adding Radix UI Tooltips, ensure `Tooltip`, `TooltipTrigger`, `TooltipContent`, and `TooltipProvider` are all correctly imported from `@/components/ui/tooltip` (note the lowercase t) and applied wrapping the Tooltip Trigger button. Set `asChild` in `<TooltipTrigger>` to avoid invalid nesting of buttons if the child is already a `<button>`. Finally, `title` attributes on buttons should be converted to `aria-label` attributes to prevent browser tooltips overlapping custom ones while remaining accessible to screen readers.
