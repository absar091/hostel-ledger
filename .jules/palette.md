## 2025-04-06 - Replacing Native Title Attributes with Radix Tooltips
**Learning:** Native `title` attributes on interactive elements provide a delayed, inconsistently styled, and poorly accessible tooltip experience. When integrating Radix UI tooltips, it's critical to explicitly remove the native `title` attribute to prevent a "double-tooltip" effect where both the custom and native tooltips appear simultaneously, confusing users and screen readers. Additionally, tooltips must be globally wrapped in `<TooltipProvider>` to prevent application crashes due to missing context.
**Action:** Always replace native `title` attributes on icon-only buttons with Radix `<Tooltip>` components, ensuring the native attribute is removed. Use `<TooltipTrigger asChild>` to prevent invalid HTML nesting, and wrap the component tree with `<TooltipProvider>`. Utilize `useTranslation` for the tooltip and `aria-label` content.
## 2026-11-09 - Icon-Only Button Accessibility Pattern
**Learning:** Found multiple instances of icon-only buttons lacking accessible names (`aria-label` or tooltips) across various components (`GroupSettingsSheet`, `ui/sidebar`, `QuickActions`, `MemberSettlementSheet`). Specifically, the sidebar toggle and group settings copy/search buttons were completely invisible to screen readers while being critical interactive elements. Additionally, when disabled elements (like buttons) are used with tooltips or need accessible names, they must be properly labeled to ensure users understand the action they are taking or why it might be disabled.
**Action:** Always ensure icon-only interactive elements have an `aria-label` or are wrapped in a Radix UI `Tooltip` that provides an accessible name. For standard toolbars and navigation components, prioritize `Tooltip` components as they benefit both visual users and screen readers (since Radix UI tooltips auto-generate `aria-describedby` or fallback to `aria-label`).
