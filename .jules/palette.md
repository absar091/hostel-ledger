## 2025-04-06 - Replacing Native Title Attributes with Radix Tooltips
**Learning:** Native `title` attributes on interactive elements provide a delayed, inconsistently styled, and poorly accessible tooltip experience. When integrating Radix UI tooltips, it's critical to explicitly remove the native `title` attribute to prevent a "double-tooltip" effect where both the custom and native tooltips appear simultaneously, confusing users and screen readers. Additionally, tooltips must be globally wrapped in `<TooltipProvider>` to prevent application crashes due to missing context.
**Action:** Always replace native `title` attributes on icon-only buttons with Radix `<Tooltip>` components, ensuring the native attribute is removed. Use `<TooltipTrigger asChild>` to prevent invalid HTML nesting, and wrap the component tree with `<TooltipProvider>`. Utilize `useTranslation` for the tooltip and `aria-label` content.

## 2025-04-17 - Keyboard Focus Rings on Global Navigation
**Learning:** While the primary focus might be on adding `aria-labels` and tooltips, many interactive elements (especially in headers and fixed navigation bars) lack proper keyboard focus visibility (`focus-visible:ring`). Without this, users navigating via keyboard (tabbing) have no visual cue of their current location. Implementing explicit `focus-visible` styles using the design system's primary colors (e.g., `focus-visible:ring-[#4a6850]`) significantly improves accessibility (WCAG Success Criterion 2.4.7 Focus Visible) without impacting mouse/touch users.
**Action:** When auditing or building navigation components, systematically check for and add `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-[theme-color] focus-visible:ring-offset-2` to all interactive elements (`<button>`, `<a>`, custom elements acting as buttons) to ensure a robust, keyboard-accessible experience.
