## 2024-05-18 - Prevent Unnecessary Re-renders from Context Getter Functions
**Learning:** In contexts that manage large datasets like `FirebaseDataContext` (`transactions`), exposing unmemoized getter functions (e.g., `getTransactionsByGroup` containing a `.filter()`) causes two issues: 1) The context provider recreates these functions on every render, unnecessarily invalidating the context `value`. 2) Consumers calling these unmemoized getters will receive a new array reference on every render, triggering costly child component re-renders (like long `TransactionList`s) even when data hasn't changed.
**Action:** When exposing utility/getter functions from a context provider, always wrap them in `useCallback` with their required dependencies. When consuming these getters to derive filtered data for a view, wrap the execution in `useMemo` (e.g., `useMemo(() => getTransactionsByGroup(id), [id, getTransactionsByGroup])`) to ensure stable array references are passed to children.
